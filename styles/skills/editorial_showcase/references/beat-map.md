# Speech to scene

Build around the speaker's argument. An explainer can progress through concepts and examples; a case can progress through task, approach, work and outcome. Keep only sections present in the speech or brief. Do not invent performance numbers or force a case structure onto an introduction.

| Speech function | First choice | Use another choice when |
|---|---|---|
| Main point / new concept | Presenter + serif heading, one short accent | No headroom: put the heading beside the presenter or use a type card. |
| Customer question / quoted request | Message card | A paraphrase is needed: label it as a summary, not a real received message. |
| Definition / concise conclusion | Full-screen neutral type card | The sentence is long: split by meaning or keep readable captions on the speaker. |
| Components / contents / categories | Document or page scene | No document supplied: use a clean diagram with approved text, not a forged document. |
| Work being explained while the person remains relevant | Presenter + lower-screen demo | A specific detail must be read: enlarge the demo or cut to a full-screen detail. |
| Several complementary examples of one subject | Three-row showcase | Fewer than three useful views: use one/two panels; never duplicate rows just to fill them. |
| Interaction / app or screen context | Phone/screen container | Shape does not suit the source: use a plain screen without cropping away the relevant interaction. |
| Values / abstract terms / short list | Editorial paper scene | No textual reason: skip the paper treatment. |
| Next step / CTA | Live presenter + concise readable text | No live tail: close on moving supplied media with the same type kit. |

## Rhythm defaults

- Presenter phrases usually hold for 2–6 s. A demonstration usually holds 3–8 s; allow more when something must actually be read.
- Add a meaningful visual change roughly every 3–6 s when the argument supports it. A changed phrase, crop or panel content can be enough; this is not an effect quota.
- A type card is a brief explanation, usually 1–4 s, not a replacement for all presenter footage.
- Use one main device per beat. Do not stack a phone, message, paper background and three-row showcase together.
- Reserve the elaborate panel handoff for explanation/demo boundaries, usually no more than once in 8–12 s. A short film may need only one or none.
- Keep the presenter recognisable across the piece and return before the CTA. Do not impose a fixed screen-time percentage on every script.

## Plan record

For each beat write: start/end, spoken words, communicative purpose, chosen device, source file/range, caption role, incoming/outgoing transition and estimated cost. Track unknown spellings separately. Include a fallback for each missing source.

When a supplied reference suggests a different treatment, keep the approved brief first and document the adaptation. Do not silently sacrifice legibility or factual accuracy to match the reference.
